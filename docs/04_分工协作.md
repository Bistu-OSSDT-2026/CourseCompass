# CourseCompass · 分工协作文档

> 版本 v0.1 · 5 人小组 · 7 天冲刺

---

## 一、成员角色

| 成员 | 角色 | 核心职责 |
|------|------|----------|
| **A** | 产品 | 决策与协调，确认功能边界，负责对外说明文案，不写代码但要对功能说「不」|
| **B** | 前端 | 所有页面开发、组件复用、移动端适配 |
| **C** | 后端 | Flask 接口、数据库模型、部署上线 |
| **D** | 数据 | 课程/教师数据收集清洗、学分规则整理、数据导入 |
| **E** | 文档/测试 | GitHub 仓库维护、接口文档、用户测试、推广 |

> **关键原则**：每人认领自己的 GitHub Issue，完成后提 PR，不要直接推 main 分支。

## 二、7 天每日分工

### Day 1 · 启动 + 定架构

| 成员 | 今日任务 |
|------|----------|
| A | 整理 Holland 问卷题目（20 题），确认推荐映射规则（类型 → 方向 → 课程） |
| B | 搭前端脚手架（Vite + React），配置路由结构，跑通 Hello World |
| C | 搭 Flask 骨架，用 AI 生成初版 SQL，建好所有数据库表 |
| D | 整理学校官网课程列表，用 AI 辅助转为结构化 Excel，准备导入 |
| E | 建 GitHub 仓库，写 README 模板，把所有功能拆成 Issue 任务卡 |

🤖 **AI 辅助**：让 AI 生成 Holland 量表中文 20 题 + 计分规则 + 六类型描述，直接复用。

✅ **当日里程碑**：前后端本地均能跑通，数据库表结构建好，问卷题目确认。

---

### Day 2 · 问卷 + 后端接口

| 成员 | 今日任务 |
|------|----------|
| A | 和 B 确认问卷页 UI 细节，确定选项措辞和跳题逻辑 |
| B | 开发问卷页（进度条 + 题目 + 选项），完成前端计分逻辑 |
| C | 写 `/api/v1/quiz/submit` 接口：接收答案 → 计算类型 → 返回推荐 |
| D | 完成课程数据导入，补充标签（Holland 类型 / 推荐方向 / 适合年级） |
| E | 用 AI 写接口文档（输入/输出格式），确保前后端字段对齐，避免联调翻车 |

🤖 **AI 辅助**：让 AI 写 Holland 推荐映射规则，例如「R 型为主 → 推荐技术研发方向 → 推荐课程有数据结构、操作系统…」

✅ **当日里程碑**：问卷可以提交，后端返回推荐结果（mock 数据也行）。

---

### Day 3 · 课程展示 + 教师页

| 成员 | 今日任务 |
|------|----------|
| A | 确认教师信息页字段和交互，明确哪些信息能从官网获取 |
| B | 开发推荐结果页 + 课程列表页（支持方向 / 学分 / 类型筛选） |
| C | 写 `/api/v1/courses` 和 `/api/v1/teachers` 接口，支持搜索和过滤 |
| D | 整理教师信息，用 AI 批量提取姓名/职称/研究方向，清洗成 JSON |
| E | 写 CONTRIBUTING.md，画简单系统架构图 |

🤖 **AI 辅助**：把老师简介粘给 AI，让它批量输出 JSON `{ name, title, research, courses }`，直接存库。

✅ **当日里程碑**：课程列表和教师列表页可以正常浏览和搜索。

### Day 4 · 评论区 + 学分规划器

| 成员 | 今日任务 |
|------|----------|
| A | 设计学分规划器交互：输入已修学分 → 展示差额 + 推荐课程 |
| B | 开发教师详情页 + 课程评论区（提交 / 展示） |
| C | 写评论接口（匿名提交 / 获取列表），加 `is_visible` 审核机制 |

| E | 写用户测试脚本，招募 2–3 名同学试用，记录反馈 |

🤖 **AI 辅助**：让 AI 写评论敏感词过滤函数 + 内容审核 prompt（检测明显违规内容）。

✅ **当日里程碑**：评论可以提交并展示，学分规划器逻辑跑通。

### Day 5 · 联调 + 样式打磨

| 成员 | 今日任务 |
|------|----------|
| A | 主导联调，逐一验证所有页面跳转路径和端到端流程 |

🤖 **AI 辅助**：前端把 CSS 丢给 AI 检查移动端兼容问题；后端让 AI 做 code review（安全漏洞 / 边界处理）。

✅ **当日里程碑**：全流程跑通：问卷 → 推荐 → 课程 → 教师 → 评论，无明显断点。

## 三、协作规范

### 每日同步（建议 5 分钟站会）

每天花 5 分钟在群里同步：
- 昨天完成了什么
- 今天准备做什么
- 有没有被什么卡住（需要别人帮助）

### Issue 认领规则

- 每人每天开工前在 GitHub 认领当天对应的 Issue（Assign 给自己）
- 完成后更新 Issue 状态，提 PR 关联 Issue
- 卡住超过 2 小时，在群里喊，不要一个人死磕

### PR 规则

```
feature/B-quiz-page     # 格式：feature/成员-功能名
fix/C-comment-api-bug
```

- PR 描述写清楚「做了什么 / 怎么测试的」
- 至少 1 人 Review 才能合并到 dev
- main 只在 Day 6 末统一合并一次

### 卡住了怎么办

| 卡住类型 | 处理方式 |
|----------|----------|
| 技术问题 | 先问 AI，还不行群里问，再不行找 C（后端）或 B（前端）帮看 |
| 功能边界不清楚 | 问 A（产品），A 5 分钟内给答案 |
| 数据不完整 | 问 D，D 优先补数据 |
| 不知道该做什么 | 看 GitHub Issue 列表，没有就问 E |

## 四、风险与应对

| 风险 | 概率 | 应对方案 |
|------|------|----------|
| 评论区用户系统太复杂 | 中 | 改为完全匿名（只留内容+时间），去掉昵称和邮箱 |
| 数据收集进度慢 | 高 | 先录 20 条课程撑起 MVP，上线后持续补充 |
| 前后端接口对不上 | 中 | E 提前写好接口文档（Day 2 完成），前端用 mock 数据并行开发 |
| 部署失败 | 中 | 提前 Day 5 就开始试部署，留 Day 6 修问题 |
| 时间不够 | 高 | 按优先级砍功能：学分规划器 > 评论区 > 教师页 > 课程列表 > 问卷 |
